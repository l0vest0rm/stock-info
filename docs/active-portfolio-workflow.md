# 分散化主动组合：工作流与当前实现

## 目标与入口

约100家研究覆盖、最多39只持仓证券，不复制指数、不追求凑满数量。基准用于评价而不是机械配仓；25席位/行业预算仅是旧示例，不能自动变成个人目标权重。

本地入口：http://127.0.0.1:8000/investment-universe.html 。首页先显示主动组合工作台：今日待办、我的组合、决策与复盘，并保留完整观察池及公司研究编辑器。

## 当前可执行闭环

1. 在「我的组合」录入账户别名、实际数量、原币每股价格、现金、折算汇率、含时区快照时间及来源。只支持无融资的股票与现金；不得把未录入资产当成已覆盖。
2. 用户设置单公司/行业权重上限及评价基准与期限。上限不预填投资建议；缺少规则会产生配置待办。允许录入超过39只的真实组合，但产生超限复核，不拒绝记录现实。
3. 按股票市值加现金计算基准币总资产、公司及一级研究行业权重。多账户同证券合并计数，多地上市按经营公司ID合并集中度；不认为A/H/ADR交易权利相同。观察池外证券保留真实金额并标明身份/分类缺口。
4. 任一价格或汇率缺失，总资产和全部权重留空；不使用不完整分母。快照超过36小时只标记需核对，不声称旧快照权重就是当前风险。
5. 只读关联现有滚动研究看板：已持仓的论点失效/经营风险进入风险复核，数据失败/过期/依赖版本变化进入数据缺口，其余未复核论点进入研究待办。未持仓公司只有当前量化门和人工论点均通过，才进入组合适配研究；不是买入建议。
6. 用户可选维持不动、已复核、延期复核，填写理由；延期须给未来时间。处理不隐藏原风险/缺口，不能更改研究论点状态，也不记作成交。依据或快照变化后重新打开复核；相同依据的计算时间变化不重复提醒。
7. 保存快照和处理记录采用版本比较并追加不可变记录，冲突拒绝覆盖。页面保留未保存编辑，需明确放弃后重新读取。最近100版可查看，旧记录不删除。每个决策保留当时待办的依据与理由。

站内待办每分钟只读刷新；关闭页面不执行页面轮询，不发外部推送。估值后台刷新继续由原服务端cron负责。当前队列是按现有研究结果生成的滚动视图，不是永久事件收件箱：尚未处理且已消失的事件不保证留存，已处理事件的证据保存在版本历史。

## 调整前后比较与动态资料

- 在「我的组合」创建假设目标组合，输入方案理由、费用和新增/提取资金，编辑目标数量及剩余现金。方案沿用原快照时间、币种、规则及现有证券价格/汇率，不通过改规则或改价格伪造改善。
- 保存后对比不调整与目标方案的证券数、股票/现金、公司/行业权重、买卖数量、总买卖金额占原总资产的比例以及资金差额。总买卖比例是双边总额/NAV，不冒充年化换手率。
- 费用未知、资金不平衡、超过39只或快照过期不能记录采纳。跨账户和多币种资金权限、实际税费、共同风险与流动性仍须人工核验。即使记录采纳，真实持仓、现金和成交记录均不改变。
- 每个方案附所依据快照及当时研究任务证据；新真实快照使旧方案无法直接采纳，须重做对比。当前工作区保留最近10个方案，历史不可变版本仍保留旧方案。
- 公司详情增加「动态资料→核验事实→更新论点」，只读现有`/api/knowledge/feed`中按证券实体标签关联的最近10条入库资料。阅读时更新，用户可刷新；不启用新抓取或模型任务。来源发布日期、读取时间和处理状态分开。空结果/失败明确显示覆盖缺口，不能称为“没有新闻”。
- 既有公司研报、估值与论点编辑器继续复用，并修正美股裸ticker到`.US`的研究接口映射。资料关联和模型提取不是事实验证，更不自动触发买卖。

## 技术所有权及边界

- 共享契约：`shared/active-portfolio.ts`；证券代码遵循观察池API的`.US`约定。
- 纯规则与验证：`src/modules/research/domain/active-portfolio.ts`。
- 唯一写入者：`src/modules/research/application/active-portfolio.ts`。
- 私有路由：`GET/POST /api/research/portfolio/workspace`、`GET /api/research/portfolio/history/:version`。只允许本地Node、loopback Host及同源请求，响应no-store；生产返回404。拒绝跨站、非JSON写入、超大请求。
- 使用已有`kv_cache`的`private-active-portfolio-v1`命名空间，`expires_at=null`。不是可清理的缓存；不进入公开研究、报告同步或静态资源。无新表、无新迁移、无模型调用。
- 浏览器不保存持仓到localStorage，不调用行情提供商；账户只用别名。操作系统账户及本地数据库文件仍属于信任边界，本功能不提供数据库加密或多用户权限系统。

## 尚未完成的上层闭环与前置门槛

以下不是当前已实现功能，不应在页面或通知中宣称已完成：

| 工作 | 所有者/前置条件 | 验收标准 |
| --- | --- | --- |
| 真实个人组合验收 | 用户录入并核对持仓、现金、规则和评价基准 | 与账户明细对账；不得用测试样例替代 |
| 资讯/公告/研报增量事件账本 | 信息管线维护者；稳定事件ID、首次可知时间、证据与论点映射 | 同事件去重，修订可追溯，不按旧闻重复提醒；未经处理的重大事件也应持久留存 |
| 个股价格/汇率自动对账 | 行情/汇率来源与交易日口径明确 | 独立日期与来源，雪球失败不切换股票行情来源，缺口不补零 |
| 自动生成有充分投资依据的调整提案 | 用户真实组合和规则；行业共同风险、成本、交易权限及情景假设 | 当前已支持人工what-if对比；自动选股/权重优化仍不能绕过未完成证据与账户检查 |
| 实际成交与组合收益 | 成交记录、现金流、分红、费用、汇率和基准口径 | 不把研究观察收益当成实际组合收益；能重建对账历史 |
| 外部通知 | 当前选择仅站内待办，不启用 | 后续若改变须明确选择渠道并授权，不从本功能推断外发许可 |

生产部署不是本轮默认动作。若后续私有功能需要远程访问，须先设计鉴权和用户隔离，不得移除loopback检查直接暴露。若需要新表须先获批准。生产远程LLM禁令继续有效。

## 验证

标准流程：`./start-local.sh`，`GET /api/health`，浏览器检查工作台，`npm run test:basic`。保留的basic入口包含组合算术/缺口、证券与公司合并、39上限、陈旧数据、语义去重、并发版本、不可变历史及私有路由回归。

浏览器保存测试使用独立临时SQLite与本地端口，不能把虚构持仓写入日常数据库。外部数据API失败须记录来源和失败边界，不弱化basic测试或把局部通过称为全量通过。
