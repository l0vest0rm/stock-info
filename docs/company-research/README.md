# 公司研究档案（长期维护）

> 资料型 Markdown 研究文档，不是行情源、股票池主数据、自动买卖指令或已部署的前端页面。首次建立：2026-10-31。

## 结构约定

- 按 **一家公司一个目录** 管理，目录优先采用其研究使用的主证券代码，如 600487.SH。多地上市的同一经营主体只建一个目录，其他证券在目录首页关联，不重复建公司。
- 每个公司目录保留 README.md（当前摘要与目录）、01-business-and-moat.md（业务与壁垒）、02-products-and-capacity.md（产品与产能）、03-financials-and-capital.md（财务、融资、治理）、04-thesis-and-monitoring.md（投资逻辑、反证、增量事件）。
- 不同公司可按实际复杂度增减专题文档，但文件名表达主题而非发布日期；已经发生的研究变更以时间戳追加到研究跟踪记录，不静默修改旧判断。
- 跨公司适用的行业供需、产品价格与技术变化，维护在 ../industry-research/，个股引用而不复制成独立的“公司事实”。

## 事实核查及更新规范

1. **公司正式披露**：注明公告日期、期间、单位和原文 URL；已披露财报数字与管理层口径、规划、假设严格区分。三季报未经审计也要注明。
2. **机构预测/行业报价**：注明研报或引用方、数据观察时间、统计口径。不得当作未来实际需求/价格、公司销售均价或一致预期。
3. **市场传闻或转述纪要**：单独写入“待验证”，不纳入已证实产品结构、订单或估值假设；缺原文时明确缺失。
4. **研究判断**：标注“分析/推断”、最强反证和下一观察指标；不能描述成公司承诺。
5. **规划≠产能落地≠实际产量≠销量≠营业收入**；不同层级（光棒、光纤、光缆、连接器、FAU）不可重复相加。
6. 不写个人持仓、成本、账户、仓位操作；私人研究历史继续使用项目原有私有工作流。
7. 新资料要优先更新已有对应主题文件，追加“变更记录/待核验项”，不持续制造相似重复文档。
8. 此目录不修改现有 config/investment-universe.json 的主数据；观察池外公司仍可先建研究档案。进入观察池时另走已有验证流程；不要自行捏造 co-xxxx 稳定 ID。
9. **文件落盘不代表自动展示**：当前不修改 Rust API、SQLite、观察池前端、原研究编辑器或任何自动抓取任务。若需前端展示，后续通过明确的数据读取/导入接口实现并测试。
