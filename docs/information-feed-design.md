## 1. 目标与范围

将“研报资讯”改为按时间浏览的“资讯”卡片流，支持按来源、内容类型、公司、主题和行业筛选。首期只接收**原始正文为文本、HTML 或 Markdown** 的文章，包括腾讯自选股、财联社等；未来可增加 X 账号来源。**原始正文是 PDF 的材料不进入资讯板块**，即使已转成 Markdown，也不为本板块下载、OCR、转换、打标或发布。文本文章附带 PDF 附件时，只处理其可用文本正文，不读取附件。

本地采集的明确新信息入库后即可在本地“全部/未分类”看到；疑似重复先短暂自动判定，不先给用户展示冗余卡片。随后本地 Node 异步用 **`gpt-6-luna`** 打公司和主题标签。行业只按版本化的“主题 → 行业”关系工程映射，不让模型再打行业。**远端只批量发布原始格式合格、已成功打标且至少有一个有效公司/主题标签的文章**；无标签、打标失败或 PDF 都不发布。采集、打标、失败恢复与发布自动运行，无逐篇人工复核。

首期不做个性化推荐、交易信号、事实核查、PDF 处理、跨大量报道的事件分析综述或全文公开转载；只合并无增量重复稿，并将明确的新进展折叠为同一话题的更新。旧资讯表和数据可清理/重建，但共享的 `knowledge_docs` 等表还被公司/研究模块使用；实际删除前须同步迁移调用方，不能误删其他功能的数据。现有“研报精选”等独立功能不因此停用。

## 3. 文章、格式与标签契约

**资讯条目**是一条可确认原始格式为文本/HTML/Markdown 的来源文章。优先以 `(source_key, source_item_id)` 确定稳定身份；缺少来源 ID 时采用规范 URL。`source_key` 是稳定平台/账号 ID，显示名称可变化；来源和“新闻/快讯/文本研报/公告”等内容类型是采集元数据筛选项，不是模型标签。

**原始格式**必须来自采集器的来源 MIME、文件类型、`access_method`、原始 URL 或已核实的来源文本 API/字段，不得只看转换后的 R2 MIME。`application/pdf`、PDF URL/文件、`remote_pdf`、`local_pdf_pending`、`markdown_from_remote_pdf` 均不准入；原始格式无法确认则留在采集诊断，不进资讯流、模型或远端。当前实现对缺正文条目也拒绝入流，等待下一次采集补齐，不凭标题猜标签。格式门禁要同时覆盖采集、打标扫描、远端发布与读取 API，防止存量数据绕过。

**语义标签**只描述文章实质涉及的规范对象，不代表来源事实真实。模型只对工程判重后保留的 `new/update` 独有内容输出多个 `{tagId, weight}`：`tagId` 为 `company:...` 或 `topic:...`，`weight` 为 1–100，用于卡片标签顺序及可选的相关性排序。`repeat` 不调用模型。仅顺带提及的不输出。不产出无人消费的解释、证据、置信度、待审候选或行业标签。代码校验 ID、权重范围、重复项、内容哈希与模型身份，不接受模型自创可发布 ID。来源自带标签可作模型输入线索，但不进入语义标签表。

主题使用版本化词表，表示可持续关注的行业细分议题，包括产品、技术、业务、产业链环节或行业特有的核心指标，粒度小于行业；每个主题声明至少一个 `industryIds`，如“银行净息差”→“银行”。行业筛选通过主题映射求并集，不存第二套行业打标结果。`业绩与财报`、`订单与中标`、`扩产与资本开支`、`分红与回购`等是横跨主题的资讯事件/公司行为；`货币政策与利率`、`财政与产业政策`、`地缘政治与供应链`等是宏观驱动或背景，不混入 `topics`。如果将来确需按这些维度筛选，应设计独立且有消费者的分类契约，不能借用主题标签。行业名本身也不冒充细分主题。主题映射过宽由开发者根据总体效果修改词表并批量重打标，不通过逐篇人工复核修补。

英文契约统一使用 `topic`：词表为 `config/information-feed-topics.json` 的 `topics`，模型输入为 `topicCandidates`，标签 ID 前缀为 `topic:`，筛选参数为 `topic`，facets 响应字段为 `topics`。旧 `theme:` 标签不再有效；`feed-tag-v4` 将旧结果标记为待重打，并在成功重打时清除旧前缀标签。重打仍遵守每日模型调用上限，不能把旧结果改名后冒充新模型输出；远端发布开关继续关闭。

提示词 Markdown 只保存稳定的任务、语义边界和输出格式，**不复制主题清单**。本地打标器每次从上述 JSON 读取 `id`、`label`，以 `topicCandidates: [{tagId, label}]` 放进本次模型输入；模型结果必须属于本次候选 ID 集合。词表内容、提示词分别计算哈希，任一变化都会触发受每日额度约束的重打标，发布器仅接受当前词表及提示词哈希。维护主题增删改时只改 JSON；只有“什么算主题/怎么选标签”等规则变化才改 Markdown。

## 4. 从信息消费者角度去重

信息流的一张卡代表**一份有增量的信息**，不代表“抓到了一个 URL”。用户不应为同稿转载、换标题重写或只调整措辞的报道反复阅读。来源原文在比较时可临时使用，但**重复内容不写入 D1/R2**；只保留一份代表正文及最小来源键/URL 映射，以防下次抓取重复处理。来源可追溯，不等于要保存每份重复正文。

| 新采集内容 | 消费者看到什么 | 持久化与后续动作 |
| --- | --- | --- |
| 同来源 ID/URL 重抓且正文不变；跨来源全文哈希相同 | 原卡片不变 | 丢弃重复正文；仅更新必要的来源 ID → 已有条目映射，无打标、无 R2 PUT、无远端文章写入。 |
| 换标题、换句式或少量模板差异，但没有新增事实/观点的高度相似稿 | 原卡片不变 | 丢弃重复正文，记录最小来源映射；不得因为新平台出现就新增卡片。 |
| 同一事件有**实质增量**，例如结果公布、数字修正、交易状态变化或新的明确观点 | 同一话题的“更新”卡片，只突出新增/修正内容；默认不重放大段旧正文，可展开之前的独有更新 | 保存新增内容的可定位原文段落、来源 URL/时间及与前次条目的关联，不保存重复段落；按新内容重新打标并合批发布最新展示状态。 |
| 表面相似但主体、口径、期间不同，或无法确认是否同一信息 | 独立卡片；可后续靠评测改进去重 | 保存原文一次并打标。不能把“10 亿”与“12 亿”、预测与实际、不同机构观点静默合并。 |

**两级纯工程判定：**先按稳定来源 ID/规范 URL 的已知版本、规范全文 SHA-256 去掉确定重复；再用有限时间窗、文本 shingle/MinHash、公司代码等召回少量近似候选，以段落差异、文本重合率和数字、日期、实体、事实状态等保护字段作确定性判断。规范化只去经过验证的来源署名、空白等模板差异，保留数字、日期、实体、否定词。高重合且保护字段一致才可判为无增量重复；能定位新增段落且关系足够明确才判为更新。跨来源保护字段冲突时保守地留作独立条目，避免误吞新数字、期间或状态。`gpt-6-luna` **不参与重复/更新判定**，只为需保留的独有内容打标签。规则无法证明重复时宁可保留，后续以样本调阈值。

对于 `repeat`，不保留新正文，不创建 `knowledge_docs` 文章行，也不调用第二次标签模型或远端发布。对于 `update`，只保存能让用户看出“新在哪里”的段落与来源指针，关联同一 `story_key`；前序独有内容仍可展开，但信息流默认只出现这个话题的最新卡片。对于 `new`，存一份完整文本。来源过滤匹配该条目已知来源键集合；集合只存键/计数等小型元数据，不保存多个相似正文。新增重复来源若仅增加来源键，在下一常规远端批次合并轻量元数据更新，不逐篇远端写入。

“是否有实质增量”要用真实样本验收：财联社/腾讯同稿、不同标题同文、同事件不同数字、预测修订、快讯→正式公告、来源撤回。重点指标是**消费者实际看到的重复卡片率**及**误吞新信息率**，后者必须优先控制。只凭公司/主题标签相同、标题相似或属于同一事件绝不能判重复。

## 5. 自动链路与状态

```text
来源采集（腾讯/财联社/未来 X）
  → 原始格式/权限检查：PDF 或未知格式不进资讯链路
  → 来源 ID / 正文哈希完全重复？丢弃新正文，仅更新必要的来源映射
  → 高相似候选？无：新条目本地可见，异步调用 gpt-6-luna 打标
                有：纯工程规则判 repeat/update/new；独有内容才异步打标
                      repeat：丢弃本次抓取正文，不新增卡片/标签/远端内容
                      update：只存新增段落，同话题最新卡片替代旧卡片位置
                      new：存一份正文，新增卡片
  → 校验标签 Schema、词表、输入哈希和实际模型标识
  → 本地原子写入独有内容/标签/状态
  → 非 PDF + tagging_status=complete + 当前内容哈希匹配 + 有效语义标签≥1？
      否：仅本地；失败自动重试，零标签待正文/词表/提示词更新后重跑
      是：进入本地待发布集合
  → 发布窗口：缺失的远端 R2 内容先上传，多篇条目与标签合批写远端 D1
  → 生产 Worker 只读已发布结果
```

本期判重在单次入库操作内同步完成，不设置模型判重等待队列。工程规则无法确定的相似稿按独立条目保守保留，仍须先完成模型打标才能发布到远端。本地允许这些条目及无标签条目可见；自动打标失败后按退避重试，不靠人工逐篇复核。

已入库条目的打标状态为 `pending | processing | complete | failed`。合法空标签数组是 `complete`，但不符合远端发布资格。传输、限流、非法输出按有限重试及退避自动恢复，设并发/每日用量上限；正文缺失优先自动补抓。崩溃后的过期任务可重认领，写结果时再核对输入哈希，防止旧结果覆盖新内容。没有逐篇人工审核队列。开发者只根据总体重复卡片率、误吞新信息率、标签误归属率、无标签率、失败率和积压调整规则/词表/提示词，再自动批量重跑。

已发布条目正文或增量改变时，旧标签不得用于新内容；新版本打标完成前不发布。若来源撤回、权限变化或重算后变为零标签，需把旧远端卡片下架；法律/权限撤回可越过常规批次立即下架。下架不是发布无标签文章。

## 6. 远端最少操作与批量发布

发布器**只看有独有内容、已打标且尚未发布的可见条目快照**，无合格变更则零远端请求。建议初值为每 15 分钟或累计 200 篇合格文章触发批次（先到者为准），最终按实际资讯量和远端成本调整；模型没完成就继续留本地，绝无“超时发布无标签”兜底。发布指纹包含条目 `doc_id`、独有内容哈希、模型标签/权重、最小来源键集合及契约版本；窗口内多次变化只发布最新快照，已发布相同指纹不重写。

先上传远端缺失的内容对象，利用内容哈希键和本地同步账本跳过已上传对象，不逐对象 HEAD；R2 每个新对象仍需一次 PUT，不能假称多对象合为一个请求。再把多篇 `knowledge_docs`、内容引用及 `knowledge_doc_tags` 合并为受 D1 请求大小约束的批次。R2 上传失败的条目不进本批 D1，其余条目照常发布；D1 失败不推进发布指纹，下批幂等重试。实施时验证所选 Wrangler/D1 批量写入的原子性，不能假定 CLI 多语句天然原子；每批用一次可靠批次结果/批量回读核对，并抽样检查生产 `/api/knowledge/feed`，不逐篇发远端校验请求。监控合格待发布量、最旧积压时间、每批文档数、R2 PUT 数、D1 调用次数和失败率。

旧“来源文章直接远端导入”路径必须停用或收敛到该发布器，防止绕过 PDF/标签门禁。生产读取接口也强制只返回原始格式合格、存在当前有效语义标签且标签输入哈希与当前独有内容匹配的可见条目；旧远端 PDF/无标签数据不能进入新流。

## 7. 存储与页面/API

首期不新建表，可重置旧资讯相关数据并调整现有表：

- `knowledge_docs`：**一行表示一份独有信息或有实质增量的更新**，不是每个抓取 URL 一行。存代表来源、原始格式、规范 URL、独有内容哈希、`story_key`、可选 `previous_item_id`、来源键集合、打标状态/契约版本/重试时间。重复稿只更新来源映射/聚合来源键，不再存正文；不同更新以 `story_key` 相连，但默认仅最新更新进入流。旧混合资讯数据可清理；因该表被其他模块消费，执行时须同步迁移调用方并限定清理范围。
- `knowledge_doc_content_refs`：`new` 只存一份完整文本；`update` 只存可直接展示的新增/修正段落，并保留原始 URL；`repeat` 不写内容对象。工程判重使用的抓取原文不另存为长期副本。原始 PDF 转出的 Markdown 不能获得资讯准入资格。
- `knowledge_doc_tags`：清除旧来源/PDF/推荐标签后，仅存可见独有条目的 `(doc_id, tag_id, weight, input_hash, contract_version)`；`repeat` 不写。成功重打标在本地事务中整体替换旧标签。
- 来源 ID/URL → 已有条目的映射是**去重索引**，可用本地压缩状态文件或经确认的现有 KV 能力保存，不保存重复正文；字段仅保留来源键、原始 ID/规范 URL、目标条目 ID、内容哈希和必要时间。开发阶段必须验证索引可重建、容量上限及崩溃恢复，不凭内存态去重。旧资讯同步账本可重置，只保留新方案的发布指纹与已上传 R2 键。若现有表/状态存储确实无法合理承载去重索引或更新关系，**新增表须先取得用户明确批准**，再写 `CREATE TABLE` 迁移、更新 schema guard allowlist 和测试。

新 `GET /api/knowledge/feed` / `GET /api/knowledge/feed/facets` 使用服务端筛选、稳定的 `(sort_time, doc_id)` 游标；默认每个 `story_key` 只展示最新一条“新信息/更新”，可展开之前的独有更新，不重复铺满首页。返回标题、**本条新增内容**摘要、来源、发布时间、文本原文入口、公司/主题标签及派生行业，不返回无权限全文。来源筛选匹配条目最小来源键集合；同维度多选 OR、不同维度 AND。**仅本地**有“未分类/失败”视图；生产不提供未分类或待去重内容。查询先确定可见条目再分页，不能分页后临时去重。原文只处理文本/HTML/Markdown 和访问权限，不保留 PDF 分支。

页面、导航、首页和 SEO 统一改“资讯”，建议 `/news.html`，替换全部站内旧链接；不保留旧 `research-news.html` 别名/重定向。生产开放须在远端数据、权限、版权和性能验收后进行。X 来源接入前仍须确认接口授权、配额、可展示内容和删除事件，不把受限全文送模型。

## 8. 分期与验收

| 阶段 | 工作 | 验收 |
| --- | --- | --- |
| 0：契约/样本 | 确认公司/主题词表、行业口径、模型可用性、来源许可；制作同稿、近似转载、标题相同不同内容、数字修订、PDF/转换 PDF 样本；盘点共享表调用方 | `gpt-6-luna` 实际返回模型正确；PDF 不进流/模型；去重误合并门禁在样本上通过。 |
| 1：本地数据与打标 | 限定清理旧资讯混合数据，建立原始格式、稳定来源身份、独有信息/更新判定与自动失败恢复；不新建表 | 同稿或无增量改写只有一张卡且只有一份正文；新数字/进展显示为同话题更新且不重放旧段落；重复稿无新增 R2 对象、无额外打标；无标签独有内容仍本地可见。 |
| 2：页面/API | 新 feed/facets、卡片流、筛选/游标、文本原文和权限，去掉旧 PDF/URL/UI 分支 | 本地 API/页面验证去重、筛选、分页、移动端、未分类与 PDF 不出现；`npm run test:smoke:pages`。 |
| 3：远端发布 | 非 PDF、独有内容、有效标签三重准入；R2 先行及 D1 合批，生产只读 | 未打标/零标签/PDF/重复稿都不发布；空批次零远端请求；远端 D1 与生产 API 均能证明已发布独有条目及标签；生产无 LLM 调用。 |

线上应监控重复候选数、自动判重率、被硬约束否决数、消费者重复卡片率、误吞新信息率、独有更新数、无标签率、打标失败率、远端积压和每篇模型/远端成本。当前仅有运行计数与失败日志，完整聚合监控尚未实现。去重阈值及打标效果由开发者依据样本和总体指标调整，不引入日常逐篇人工复核。
