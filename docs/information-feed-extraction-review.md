## 日期区间与重试提示修订：v9

- 期间支持正文逐字出现的 ISO 日期区间、带双端年份或不带年份的中文月日区间；校验真实日历日期和起止顺序，不根据发布日期补年份。无年份区间按月日排序，不推断跨年；2月29日在未指定年份时允许。支持正文中的“本周/上周/下周”。
- 提示词与解析器同步；冻结 v8 合同以保持历史成功记录可读，新提取使用 v9。仍保留整批结果校验，不丢弃错误记录伪装成功。

## 类别复核修订：v8

用户放开类别增减后，按实际待审信息和白名单覆盖范围重新审查。结论不是“所有问题都是模型不听提示词”：原目录偏公司公告和财务指标，缺少产业运营及宏观事项，迫使模型硬套或产生候选；另一些候选只是信息类型组合过窄或类别边界不清，不能一律新增。

### 增加 13 个可复用业务类别（56 → 69）

| 范围 | 新类别 | 依据和边界 |
| --- | --- | --- |
| 生产经营 | `production_volume` 产量 | 特斯拉机器人和秘鲁铜产量候选；实际产量不同于产能、出货量 |
| 供需库存 | `demand_change` 需求变化、`supply_change` 供给变化、`inventory` 库存 | 白名单覆盖商品供给库存；主题导入意愿是需求判断，不必套商品涨价类别 |
| 运营与建设 | `operating_status` 运营状态、`project_progress` 项目进展 | 管道恢复、炼厂停运、工厂投产、工程建设节点均有实际待审样本；不再按行业或设施名称分别造类别 |
| 宏观 | `inflation` 通胀、`economic_activity` 经济运行、`fiscal_position` 财政状况 | 通胀判断、GDP预测、公共债务等有明确目录缺口；通胀、政策决定和公司财务互不替代 |
| 金融条件 | `exchange_rate` 汇率、`liquidity` 流动性 | 汇率议题、央行逆回购规模等不能当作企业经营数据或政策已发生变化 |
| 特定经济事件 | `resource_discovery` 资源发现、`trading_status` 交易状态 | 资源储量发现、监管停牌候选与产能、上市并不等价 |

新增类别的期间设为可选，以便承接有价值的非数值判断、当前运营状态与相对期间；不削弱既有财务指标的必填期间要求。期间可原样保留正文明确出现的有限集合相对表达（如“近几个月”），避免迫使模型编造月数；数值预测仍须精确财年和完整口径。

### 扩展而非新增的事项

- 投资、资本开支允许预测和观点，研发支出、产品研发、产能及扩建允许预测。高盛对多家公司合计AI基础设施支出的预测归资本开支，不另造“行业AI支出预测”。
- 项目签约说明覆盖明确商业项目的实质洽谈，但保留未签约状态；合同中标仅描述已经获授的订单/合同。监管批准明确包括决定准入的主管机关验收。
- 给投资/收购/资本开支/扩建、项目签约/合同中标/战略合作、研发验证/需求/客户关系补充优先归类边界，防止同一信息重复抽成多个近似类别。

### 保留和不增加

- 保留既有财务及银行专属指标；短期资讯样本出现次数少，不等于指标没有意义。金额与增速、一般资本充足率与核心一级资本充足率不能机械合并。
- 保留旧类别 ID 以保证历史过滤和发布兼容；宽泛的 `capital_allocation_outcome` 明确限于已披露回报/损失，不作兜底。此次没有为凑精简数而删除有效类别。
- 不恢复“行业观点”，不增加“其他资讯”“外交会晤”“体育赛事”“动物旅居”等兜底或非投资类目录。候选仍需要先满足信息价值和投资相关性。
- v7 合同加入冻结列表，v8 新提取使用新目录，旧记录不靠改字段冒充新结果。

### v8 实测边界

本地对 11 篇真实资讯使用支持的处理脚本重提取，含原有难例与其他运营、建设、财政及流动性样本。最终 10 篇形成新合同结果（包含一篇无有效信息的空结果），秘鲁铜产量样本仍因模型生成的主体“秘鲁铜产量”未逐字出现于陈述而被现有校验拒绝，保持失败状态，不强行写入。过程中的字段错误按原有退避规则重试，未跳过校验。运行快照位于忽略的 `data/local/information-feed-category-review-v8.json`。

已确认主要分类：特斯拉实际产量 → `production_volume`；哈玛克通胀压力观点 → `inflation`，货币政策主张仍为 `policy_change`；光刻胶国产导入观点 → `demand_change`，验证进展仍为 `product_development`；输油管道恢复/工厂投运 → `operating_status`；工程建设节点 → `project_progress`；GDP预测/公共债务 → `economic_activity`/`fiscal_position`；AI基础设施支出预测 → `capital_expenditure`；央行逆回购规模 → `liquidity`。

“生成完成”不等于语义全对：抽样仍发现投资口号被保留、项目就业人数误归项目进展、预计送电量误归实际产量，以及部分预测遗漏判断者。类别缺口已补不代表模型质量问题消失；没有为这些错误随意放宽类别说明或手改结果。本轮只对实际覆盖的样本主信息作验证，不以调优集宣称整体准确率，也不以类别扩充作为生产发布依据。

## 范围与验收

目标：提取原文有价值的信息与观点，主体不局限于公司；不新增业务类别，不猜匿名公司，不把观点改写成事实。检查链路为本体配置 → 实际模型输入 → 解析与存储 → 本地资讯 API。保留已有公司映射、白名单和生产禁止模型调用的边界。

实施顺序：确认现有数据和合同 → 修正配置及提示词 → 本地模型抽样重跑 → 校验存储、API、历史合同兼容及基础测试。以下样本用于迭代调优，不是独立测试集，不能据此宣称整体准确率。

## 确认的问题及修改

1. **把非公司主体和观点混成新类别。** 撤销 `industry_outlook`；原有类别 ID 集合保持不变。主体按每条信息的实际范围选择，公司专属事项仍用公司，行业信息可以用产品、技术或主题。
2. **目录已有定义但未充分进入模型输入。** 原先只传类别英文 ID、信息类型和期间策略，没有主体类型或中文含义。现在从 `knowledge-ontology.json` 传入主体类型、类别中文名及关键语义边界；前端标签也由该目录生成。
3. **部分业务类别不能承接观点。** 为既有价格变化、产品研发、政策变化允许 `opinion`，为政策变化允许 `forecast`。不增加类别，不全面放开所有类型组合；营收等指标的期间要求保留。
4. **禁推理与禁泛泛解读容易误伤原文观点。** 明确区分“提取原文已有判断”和“模型自行推断”。允许无署名但有具体内容的原文判断，保留预测、条件和发言者归属；匿名公司的业务不能改写成行业事实。
5. **容易硬套近似类别。** 明确产量≠产能≠出货量、一般通胀评论≠政策决定，保留待审候选机制。候选不会自动新增正式类别。
6. **解析错误缺乏定位信息。** 返回具体字段/类型/期间原因，并严格拒绝非字符串及非自有目录项的 category；不静默删除不合规记录。
7. **改提示词会影响旧记录可见性。** 冻结 v5/v6 已产出数据的合同；当前使用 v7。新提示词不伪装成旧结果，旧存储迁移仍只验证 v5 来源。
