> 2026-09-25 本地阶段性验收；远端发布开关保持关闭。此记录区分“流程运行正常”和“标签语义符合产品预期”，不把模型调用成功等同于标签质量达标。

**后续命名切换说明：**主题英文契约已统一为 `topic` / `topic:`，标签契约升至 `feed-tag-v4`。2026-09-25 当日模型调用计数已达 200 次上限，本轮只验证了新契约的类型检查、页面/API 筛选和远端门禁，尚无新契约的真实模型打标样本；旧契约结果需后续按日配额自动重打，以下打标语义抽样仍是历史结果，不应视作 `feed-tag-v4` 的质量验收。

**主题词表复核：**`feed-topics-v2` 已移除原词表中混入的业绩、订单、扩产、分红等事件类型及宏观政策背景，并将“银行”“医药”等行业级条目换为可映射行业的细分主题。旧词表结果在本地显示为待重打，远端发布器不接受旧词表哈希；当日调用额度已满，仍须等待后续自动重打与新样本验收。

## 验证范围与结果

| 环节 | 实际验证 | 结论 |
| --- | --- | --- |
| 采集与格式门禁 | 财联社 JSONL、腾讯 JSON 实际入库；文本/PDF/转换 PDF/未知格式自动化样本 | 文本进入；PDF 与无法确认原始格式的内容不进资讯流。 |
| 工程去重 | 同源重抓、跨源同稿、号码变化、来源署名差异的回归样本；存量同标题双卡复查 | 规则不依赖模型。发现两组由来源模板造成的真实重复卡，修正规范化后合并并删除了两份冗余本地正文。其余同标题对尚有高相似模板稿与明确不同正文，未在证据不足时贸然合并，仍需继续标定。 |
| 异步打标 | 本地真实调用 `gpt-6-luna`；校验实际响应模型、JSON 结构、词表 ID、权重、输入哈希、标签契约及失败重试 | 调用和写入流程正常；本轮无打标失败。旧契约标签在页面隐藏，也不能进入新发布批次。 |
| API 与页面 | 本地 `/api/knowledge/feed`、facets、story、来源/公司/主题/行业/状态筛选、游标分页及 `/news.html` | API 实测通过；完整页面冒烟中资讯检查通过。旧页面为 404。 |
| 远端门禁 | `publishRemote=false` 下运行发布器 `--apply`，并检查本地发布状态 | 输出 `skipped`，0 条远端已发布；未执行远端 R2/D1 写入或生产验收。 |

另用隔离的临时 SQLite 与内容目录跑了真实端到端样本，不污染日常资讯库：同一来源文章先入库为 `new`，追加净息差新数字后入库为同 `story_key` 的 `update`，更新正文只保存新增段落；两条均实际调用 `gpt-6-luna`，得到“银行净息差”主题及派生银行业。发布器 dry-run 只选最新已打标更新（1 条），`--apply` 因开关关闭而跳过。再投喂跨来源同正文得到 `repeat=1`，文档和本地正文对象仍各为 2；PDF 来源得到 `pdf_origin` 拒绝。临时库和内容已清除。

## 标签语义抽样

样本为最新一批财联社快讯及定向挑选的腾讯长文，**不是总体随机抽样**。其作用是发现系统性错误，不能推断全量精确率。当前词表较窄，空标签表示“没有足够相关的已定义公司/主题”，并不等于模型未运行。

截至 2026-09-25 16:05（北京时间），1416 条本地资讯中，67 条曾按当时的 `feed-tag-v3` 契约打标，其中 33 条有至少一个有效标签、34 条为空标签；17 条含公司标签，27 条含主题标签。这是历史快照，不代表新 `topic:` / `feed-tag-v4` 契约的覆盖率；旧契约标签不会在当前页面显示或进入远端发布批次。大量条目仍待按每日额度处理，因此这些数字不能作为全量覆盖率。

| 样本 | 当前判断 |
| --- | --- |
| 特斯拉印度服务网络、特斯拉 Semi 量产 | `company:TSLA.US` 与新能源汽车主题合理。 |
| Meta 目标价调整 | 最初因英文别名大小写未匹配而漏标；修正候选召回后得到 `company:META.US`。不应仅因报告出自投行就标“券商与资本市场”。 |
| 存储板块异动、光通信板块长文 | 存储芯片/光通信主主题及主要公司通常正确，权重排序基本反映主次；但长文中有权重 36–55 的背景性政策/公司标签，信息流展示略显嘈杂。 |
| SK 海力士、三星新闻 | 旧共享别名把韩国代码误当深市代码；本期资讯候选已排除两个已核实的错误映射，重打后不再产生对应的错误公司标签。旧研报代码识别的源头问题仍应单独修复。 |
| “黑芝麻智能”出现在港股综述 | 不再误标为 A 股“黑芝麻”；文中真实涉及的其他公司、地产主题仍可打标。 |
| 国际军事、足球、普通客运等快讯 | 当前投资主题词表下空标签基本合理；这些内容本地可见但不会发远端。 |
| 高阶智能驾驶研报、诺和诺德/国外公司、部分大宗与汇率快讯 | 空标签或只打主题，主要原因是词表和公司候选库覆盖不足，不应简单归咎于模型调用失败。 |

**阶段性判断：**标签的输入校验、自动化状态与主要公司/主题归属已经可用，但尚不能确认“整体标签效果符合预期”。一是当前公司候选依赖共享别名库，既有不完整也有历史误映射；二是主题词表只覆盖部分投资主题；三是长文低权重标签需要裁剪或重新定义权重门槛。远端发布继续关闭是正确门禁。

抽样中的多主题腾讯长文出现 7 个权重低于 60 的标签（例如“光通信引领反弹”同时挂上低权重的业绩、融资上市和货币政策）。这些段落确实存在于全文，但不一定是消费者筛选该文章的理由；当前实现仍会展示它们，因而**精度门槛尚未通过**。不能只按“标签在正文里出现过”判合理，应按文章主线与筛选后的用户预期判断。

行业筛选只由主题映射生成。当前“业绩与财报”等横向主题不映射行业，部分公司资讯即使已有公司/业绩标签也无法按行业检索；这不是模型漏打“行业”，而是细分行业主题的词表覆盖不足。若行业筛选是首期核心能力，需优先补齐行业相关主题，再做抽样验收。

## 容量与后续验收门槛

- 当前本地自动上限为每 15 分钟最多 20 次、每日最多 200 次模型调用。历史回填量超过千条，最新规则需要逐批重打；不要为了声称“全量通过”绕过额度。
- 在远端发布前，至少复查分层样本：财联社短讯、腾讯长文、无标签、单/多公司、多主题、跨源重复、增量更新、数字或实体冲突，以及 PDF/未知格式。
- 优先量化**误归属、漏掉核心主题、低权重噪声、无标签原因及消费者重复卡片**，而不是仅看调用成功率。需先确认首期远端究竟只发布已定义投资主题，还是希望涵盖更广泛的财经/国际快讯；该选择决定词表是否扩展。
- 建议下一轮先把“文章主线或独立且足够重要的段落”作为主题准入，并对低权重标签做展示/筛选门槛，再用分层样本测误归属；公司候选应持续清理历史错误映射并补足目标公司覆盖。不要通过让模型自行创造公司 ID 来掩盖别名库缺口。
- 远端迁移、R2/D1 批量写入、生产只读 API 与权限验收均未执行，不在本次“本地全链路”结论内。
- `npm run test:feed`、类型检查、schema guard、运行时边界及本地资讯 API 通过；完整 `test:smoke:pages` 的资讯项通过，其他 14 项因现有雪球 Cookie 返回 `400016` 失败，不能把整套页面冒烟称为全通过。
