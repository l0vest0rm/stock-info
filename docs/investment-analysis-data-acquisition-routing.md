# 投资分析数据获取与路由能力

> 状态：流程验证后的能力边界整理
>
> 验证对象：中际旭创（300308.SZ）
>
> 验证日期：2026-08-06
>
> 目的：明确每类投资分析数据应通过结构化 API、模型 Web Search、文档抽取或派生计算中的哪一种方式获取，以及哪些数据不能依赖模型补齐。

## 1. 结论

模型加 Web Search 是结构化来源之外的增量能力，不是所有数据的默认入口。它尤其适合：

- 自动识别公司主营、产品、客户、地区和商业模式；
- 从年报、季报、公告、业绩材料中提取经营数据；
- 找到公开行业市场规模、出货量、价格和增速；
- 整理同行公司的同类数据；
- 形成带来源链接、原文摘录、期间和单位的研究底稿；
- 在输入口径一致时完成简单计算。

但它不能稳定解决公开资料本身不存在的问题。尤其不能仅凭模型搜索得到：

- 公司在某个细分产品上的精确 SAM；
- 公司 400G、800G、1.6T 等产品的未披露收入、销量和 ASP；
- 完整、同口径、覆盖全市场的一致预期或市场份额；
- 付费行业数据库中的详细拆分；
- 客户认证、客户采购额和竞争对手真实订单等非公开事实。

因此，模型的职责是“发现、读取、抽取、解释”，而不是替公司或行业补造缺失数据。数值、单位、期间、口径、可比性和最终计算仍应由程序校验。

## 2. 获取方式路由与结构化优先

模型搜索不是默认数据入口。凡是已有免费、稳定、字段明确的结构化来源，应先由现有采集器/API 获取；模型只处理结构化源没有覆盖的语义、附注、解释和交叉校验材料。

### 2.0 获取方式标记

| 标记 | 获取方式 | 适用内容 | 是否允许模型直接生成数值 |
| --- | --- | --- | --- |
| `S` | 现有免费结构化 API/采集器 | K 线、三表、证券主数据、13F、宏观序列、公告元数据等 | 不允许；数值来自源记录 |
| `O` | 模型 Web Search 回链公开原文 | 行业公开数字、公司公告正文、监管/法院事件、同行经营披露 | 不允许脱离原文；必须保留链接和摘录 |
| `X` | 模型从 PDF/HTML/电话会等半结构化材料抽取 | 分部、客户、产品、订单、产能、债务附注、管理层指引 | 不允许无证据补齐；需程序复核 |
| `D` | 程序确定性派生 | 比率、ASP、市场份额、TAM 公式、同比和 CAGR | 允许按显式公式计算，不由模型随意取值 |
| `M` | 模型解释与归纳 | 商业模式、竞争关系、风险传导、证据冲突说明 | 只能生成带证据的解释，不生成事实数值 |

一项数据可以有组合标记，例如 `S + X` 表示数值来自结构化字段、附注含义来自文档抽取，`S + O + D` 表示公司分子来自结构化源、行业分母来自公开原文、结果由程序计算。

### 2.1 已有结构化来源的数据

| 数据 | 首选结构化来源 | 直接用途 | Web Search 的剩余用途 |
| --- | --- | --- | --- |
| K 线、价格、成交量、成交额 | 现有 Xueqiu K 线路径 | 收益、回撤、波动、基准日价格、估值历史 | 只查行情异常的公告或解释，不重新搜索行情数值 |
| PE、PB、PS、PCF 等行情字段 | 现有 Xueqiu 行情/快照字段，必要时程序复算 | 历史估值分位和估值基准 | 核查口径差异，不把搜索结果作为第二行情源 |
| 利润表、资产负债表、现金流量表 | A 股/港股东财；美股 Yahoo | 财务趋势、现金流、偿债、ROE/ROIC、估值输入 | 补充附注、重述、会计解释和法定原文交叉校验 |
| 证券搜索与基础身份 | 现有证券搜索、证券主数据和 `getSecurity` 路径 | 代码、名称、市场、证券类型 | 补充股份类别、ADR、VIE、控制链等结构化源没有的字段 |
| 13F 和已有机构持仓数据 | 现有 13F/机构持仓结构化路径 | 机构名单、季度持仓、持仓变化 | 只查 13F 文件解释、机构策略或未覆盖的申报类型 |
| 宏观时间序列 | 现有宏观模块及 FRED、NY Fed、HKMA 等适配器 | 利率、汇率、通胀、就业、信用和宏观事件 | 查公司或行业如何暴露于宏观变量，不重新采集同一序列 |
| 公告列表和披露元数据 | 现有 CNINFO、东财、SEC/HKEX 结构化列表路径 | 公告日期、标题、类型、链接、财报日历 | 读取公告正文、抽取经营事实和判断事件影响 |
| 基金净值及基金已有持仓字段 | 现有基金数据路径；基金净值遵守 Eastmoney-only 约束 | 净值序列、基金比较、已有持仓字段 | 解释基金报告和补充未结构化的投资理由 |
| 公司报告/新闻候选列表 | 现有报告、新闻和公告候选接口 | 候选标题、日期、来源和链接 | 打开原文，提取预测数字、管理层表述和事件内容 |

这些数据仍然属于研究所需数据，不能从文档中删除；这里只规定它们的首选获取方式。模型 Web Search 负责补充结构化源没有覆盖的字段，不重复采集同一数值。

### 2.2 不能因为“模型也能搜到”而重复接入

以下数据即使搜索引擎能返回，也不应把搜索结果写成主值：

- 日线价格、成交量和市值；
- 三张财务报表的原始数值；
- 已有 13F/机构持仓季度数据；
- 宏观指标的正式时间序列；
- 证券名称、代码和市场映射；
- 公告列表中的日期、标题和 URL；
- 已有结构化股息、基金净值和行情估值字段。

搜索得到的同一数字最多作为异常核查材料，不能形成第二套自动回退来源。结构化来源缺失、字段为空、期间错误或口径不明时，应记录为数据缺口并进入来源健康检查，而不是静默改用搜索结果。

### 2.3 数据路由规则

```text
目标字段
  → 是否已有免费结构化来源？
      → 是：结构化采集器/API 为主，模型不搜索同一数值
      → 否：是否存在公开原文或半结构化材料？
          → 是：模型 + Web Search 提取并回链原文
          → 否：标记不可得，不由模型补估
```

结构化来源仍需保留来源 ID、抓取时间、期间、单位、币种和健康状态；“排除 Web Search”不等于不做校验，而是避免重复建设和来源竞争。

## 2.4 聚合获取原则：按信息目标建包，不按字段或文档类型搜索

同一份年报、公告、研报或行业报道通常同时服务商业模式、财务附注、竞争、TAM、风险和预测多个模块。不能为“产品”“客户”“产能”“订单”“资本开支”“风险”等字段分别发起搜索，也不能把任务限定成只读某一种文档；应按研究所需的信息目标建立聚合包，再从多类高质量资料中一次性覆盖相关字段。年报和监管披露是重要事实基线，但不是任务边界。

### 2.4.1 采集包定义

| 采集包 | 一次性覆盖的内容 | 主要来源 | 产出对象 | 默认获取方式 |
| --- | --- | --- | --- | --- |
| `security_snapshot` 证券快照包 | 代码、名称、市场、币种、证券类型、股本、价格、K 线、估值和已有机构持仓 | 现有结构化 API | 证券快照 | `S`，并行批量请求 |
| `financial_snapshot` 财务快照包 | 三表、财报期、币种、会计准则、年度/季度/TTM 序列、基础派生指标 | 东财/Yahoo 及现有财务读模型 | 财务快照 | `S + D` |
| `latest_annual_report` 公司经营与结构包 | 主营、产品、客户、地区、分部、产能、研发、资本开支、治理、风险、债务和管理层表述 | 年报/监管披露为事实基线；公司 IR、公开研报、行业资料和权威媒体补充解释与缺口 | 公司经营信息包、指引/风险候选 | `O + X`，按目标跨来源聚合 |
| `recent_filings` 经营变化包 | 最近 12 个月的经营、产品、订单、管理层指引、融资、回购、审批、催化剂与风险变化 | 公司/交易所/监管材料为事实基线；公开研报、行业资料和权威媒体补充影响解释 | 事件包、变化包、更新指引包 | 元数据 `S`，内容 `O + X` |
| `industry_market` 行业市场包 | 行业定义、TAM 候选、需求、供给、价格、库存、产能、行业增速、产品结构、统计口径 | 官方统计、协会、公开行业报告和产业链披露 | 行业事实包、TAM 输入包 | `O`，按行业/市场边界聚合搜索 |
| `peer_set` 同行竞争包 | 同行名单、产品边界、收入、销量、产能、份额、价格、战略动作和可比性 | 同行财报、公告、IR、公开行业资料 | 同行事实包、可比性矩阵 | 结构化财务 `S`；经营细项 `O + X` |
| 内部研报预测账本 | 项目已导入研报的目标期间、口径、修订、来源身份和独立性 | 内部报告/知识处理与来源预测账本 | 来源预测记录、口径校验和受控汇总 | 内部处理优先；不通过 Web Search 重复获取 |
| `forecast_consensus` 外部预测补充包 | 仅在内部账本缺少所需外部前瞻材料时补充行业/公司公开预测 | 行业协会、官方机构、产业链公司公开原文 | 外部前瞻事实包 | `O`，用户明确点击；不能替代或混成内部研报一致预期 |
| `event_risk` 事件风险包 | 监管、诉讼、审计、重大合同、产品、审批、债务和证伪事件 | 监管、法院、交易所和公司公告 | 风险事件包、催化剂包 | `S` 列表 + `O + X` 正文 |

### 2.4.2 一个信息包服务多个模块

以公司经营与结构包为例，一次任务先从年报建立基线，再按信息缺口补充其他高质量资料，并同时产出：

```text
公司经营与结构信息
  ├─ 公司身份与上市结构
  ├─ 商业模式、产品、客户和地区
  ├─ 分部收入、利润、资产和经营 KPI
  ├─ 产能、销量、订单和资本开支
  ├─ 财务附注、债务、减值和或有事项
  ├─ 治理、关联交易和管理层指引
  ├─ 行业描述、竞争者和市场边界线索
  └─ 风险、证伪条件和下一次刷新触发器
```

这些结果分别写入不同事实表或证据记录；每条记录保留自己的来源链接、发布日期和口径。同一资料可以覆盖多个模块，不能为每个字段再次搜索；第三方分析必须注明判断主体，不能伪装成公司已确认事实。

### 2.4.3 推荐的单公司首轮调用顺序

在结构化批量采集完成后，首轮只建立以下任务：

1. 一次公司经营与结构包：以最新年报为基线，围绕公司经营、分部、治理和风险目标补充公开研报、行业资料和权威媒体信息；
2. 一次经营变化包：覆盖财报基线之后的经营、产品、订单、指引、催化剂和风险变化，不限定为公告文档；
3. 一次行业市场包：围绕主营二级赛道，统一搜索行业定义、市场规模、产品结构和增速；
4. 一次同行竞争包：先确定同行池，再批量抽取同行经营和市场资料；
5. 预测与估值页默认读取内部研报预测账本；仅在用户需要账本之外的外部前瞻材料时建立外部预测补充包。事件风险包也仅在需要时建立，不为每个预测数字单独搜索。

推荐的首轮调用顺序不是固定调用次数；如果结构化来源已有某个包的完整字段，就跳过该包，只搜索缺口。首轮之后，只有新增报告、来源过期、字段冲突或研究命题触发刷新时才重新搜索。

### 2.4.4 搜索任务的输入和输出边界

每个 Web Search 任务都应明确：

- 搜索对象和报告期；
- 一次要覆盖的字段集合；
- 允许的来源类型和来源优先级；
- 同一原文可服务哪些字段；
- 不能找到时统一返回 `unavailable`，而不是继续为单个字段盲目扩搜；
- 每个事实保留来源 URL、标题、发布日期、原文摘录和页码/段落。

模型返回的不是“某个字段的答案”，而是一个可复用的来源包：

```json
{
  "source_document": {},
  "evidence_records": [],
  "covered_fields": [],
  "missing_fields": [],
  "conflicts": [],
  "refresh_triggers": []
}
```

### 2.4.5 去重、缓存和再搜索条件

同一来源按 `canonical_url + source_date + period + content_hash` 去重。来源包落库后，后续模块只读取证据记录，不再次触发 Web Search。

只有以下情况允许重新搜索：

- 结构化来源或来源包健康检查失败；
- 出现新的年报、季报、指引或重大公告；
- 原有事实已过期；
- 同一事实出现冲突，需要更高等级原文；
- 新的行业模板需要之前未采集的字段；
- 用户明确要求扩大研究范围。

这套规则把“搜索成本”从字段级变成来源包级，把一个来源的抽取结果复用于多个 Tab，同时保留每个事实的来源和口径。

## 3. 模型 + Web Search 的增量事实

这里的“直接获取”是指公开资料中通常存在明确表述，模型可以找到原文并抽取为结构化记录；不代表每家公司、每个期间都一定披露。下表是“字段能力清单”，不是搜索任务清单；实际执行时应按 2.4 节的采集包批量完成。

| 字段主题 | 默认归属采集包 |
| --- | --- |
| 主营、产品、客户、地区、收入确认 | `latest_annual_report`（公司经营与结构目标包） |
| 分部、产能、销量、订单、资本开支 | `latest_annual_report` + `recent_filings` |
| 治理、债务、附注、审计、风险 | `latest_annual_report` + `event_risk` |
| 行业规模、需求、供给、价格、产品结构 | `industry_market` |
| 同行收入、产品、份额、战略动作 | `peer_set` |
| 管理层指引、机构预测和修订 | 公司指引用 `recent_filings`；机构预测和修订以内部研报预测账本为主，`forecast_consensus` 只按需补充账本外公开前瞻材料 |

| 数据类别 | 可获取字段 | 常见公开来源 | 获取方式 | 适合的研究功能 | 可靠性边界 |
| --- | --- | --- | --- | --- |
| 公司与证券身份 | 公司名称、证券代码、交易所、上市市场、证券类型、报告期、币种 | 交易所、年报、招股书、公司 IR | 结构化主数据；Web Search 补充复杂权利结构 | 研究对象映射、跨市场切换 | 股份类别、ADR 比例、VIE 和控制链可能仍需文档核验 |
| 主营与业务边界 | 主要分部、产品/服务、收入来源、客户类型、地区、渠道、收入确认方式 | 年报、招股书、业绩说明会、公司产品资料 | Web Search + 文档抽取 | 自动选择行业模板和 TAM 方程 | 业务描述通常比可计算的分部金额更完整 |
| 分部经营数据 | 分部收入、利润、资产、地区收入、销量、产量、产能、订单、积压 | 年报、半年报、季报、经营公告 | 三表/结构化字段复用；未结构化字段 Web Search + 文档抽取 | 业务驱动树、分部比较、SOTP 输入 | 细分产品、客户和速率经常不披露 |
| 资本配置与公司行动 | 分红、回购、增发、配售、解禁、并购、处置、融资、偿债 | 交易所公告、年报、股本变动公告 | 事件列表/API 为主；公告正文由 Web Search + 文档抽取 | 每股价值、净回购、催化剂、稀释 | 事件容易获取，完整历史序列和最终执行金额需去重核对 |
| 治理与管理层 | 控股股东、董事会、审计意见、关联交易、薪酬、激励、减持、质押 | 年报、代理声明、权益变动公告、监管文件 | Web Search + 文档抽取 | 治理风险、稀释、管理层校准 | 关键控制关系和关联方需要多份原文交叉确认 |
| 财务附注事实 | 应收账龄、存货结构、减值、债务期限、利率、租赁、担保、或有负债、研发项目 | 年报、季报、审计报告、债券公告 | 三表结构化 API + Web Search/文档抽取附注 | 盈利质量、偿债、压力测试 | PDF 表格和脚注抽取容易发生列错位，必须保留页码和原文 |
| 管理层指引 | 收入、利润、资本开支、产能、出货、产品进度、订单指引及修订 | 业绩稿、电话会、公告、演示材料 | Web Search + 文档抽取 | 预测、催化剂、指引兑现率 | 指引常是区间或条件性表述，不能当作实际值 |
| 公告与事件 | 财报发布、产品发布、审批、重大合同、处罚、诉讼、审计、债务到期、股东大会 | CNINFO、HKEX、SEC、交易所、法院和监管网站 | 公告元数据 API；正文 Web Search + 文档抽取 | 风险台账、事件日历、自动刷新 | 搜索结果页只能发现线索，结论必须回到原文 |
| 行业公开事实 | 行业收入、出货量、价格、库存、产能、资本开支、渗透率、增速 | 官方统计、行业协会、公开行业报告、产业链公司披露 | Web Search + 原文抽取；有稳定官方序列时优先 API | 行业周期、TAM 候选、正常化利润 | 行业边界和统计口径常不一致 |
| 同行公开数据 | 同行收入、销量、产能、产品结构、市场份额、价格和战略动作 | 同行年报、公告、公司 IR、行业机构公开稿 | 财务数值结构化 API；经营细项 Web Search + 文档抽取 | 竞争、份额、相对估值 | 必须逐项确认产品、地区、期间和收入口径 |
| 宏观与估值输入 | 利率、汇率、通胀、就业、信用利差、行业指数和官方日历 | 央行、FRED、NY Fed、HKMA、官方统计机构 | 现有宏观 API/适配器；Web Search 仅补解释 | DCF、压力测试、跨币种比较 | 模型可以找到序列，但基准日、频率和修订版本需程序管理 |
| 市场与证券风险 | 做空、质押、内幕交易、融资余额、停牌、退市、交易制度 | 交易所、监管、正式申报 | 结构化市场/申报 API；缺口由 Web Search + 原文抽取 | 证券层风险 | 三地覆盖和更新频率差异很大 |

## 4. 最适合模型抽取的半结构化资料

以下资料通常不是稳定 API，但很适合模型按字段提取：

### 4.1 年报、季报和公告

建议提取为“事实记录”，而不是直接生成摘要：

```text
主体、证券、来源文件、发布日期、报告期、事实类型、指标名称、数值、单位、币种、产品边界、地区边界、原文摘录、页码、来源链接、实际/预测/指引/假设、置信状态
```

适合抽取的内容包括：

- 分部收入和利润；
- 产量、销量、产能、利用率和交付；
- 客户和供应商集中度；
- 订单、积压、合同期限和续约；
- 研发、资本开支、项目进度和主要产品；
- 债务期限、契约、担保和或有事项；
- 管理层指引和前后版本变化；
- 审计意见、减值、诉讼和监管事项。

### 4.2 行业报告公开页和新闻稿

模型可以获取公开网页中明确写出的：

- 行业市场规模；
- 出货量和增长率；
- 产品结构；
- 公开市场份额；
- 未来年度预测；
- 统计口径和报告边界。

但付费报告目录、搜索摘要、媒体转述和“据某机构估计”不能直接进入已验证事实表。必须保留原始公开正文；正文没有数字时，最多作为待追踪线索。

### 4.3 电话会和业绩说明会

模型适合提取管理层对销量、价格、产能、客户认证和资本开支的表述，也适合把问答中的条件与限制整理出来。

电话会内容应标记为 `管理层指引` 或 `来源观点`，不能直接标记为已观察事实；会后实际结果需要回到正式财报校准。

## 5. TAM、SAM、SOM 的实际能力边界

### 5.1 TAM：相对容易获得，但必须分层

模型通常可以找到以下 TAM 候选：

- 官方或行业机构公布的行业收入；
- 行业出货量、终端数量、渗透率和 ASP；
- 客户资本开支、项目数、用户数或患者数；
- 同行收入或出货汇总形成的供应商市场规模。

如果公开输入齐全，也可以计算：

```text
产品 TAM = 终端数量 × 渗透率 × 单机用量 × ASP
项目 TAM = 项目数 × 单项目价值
软件 TAM = 潜在客户数 × 付费率 × 客单价
平台 TAM = 活跃用户 × 使用频率 × 单次金额 × 变现率
资源 TAM = 可售产量 × 产品价格
金融 TAM = 可服务资产/交易规模 × 份额 × 利差/费率
医药 TAM = 患者数 × 渗透率 × 疗程价格 × 成功概率
```

但模型只能使用已经找到的输入。缺少 ASP、分速率出货、产品拆分或重复计算排除项时，必须输出“部分可得”或“不可计算”。

### 5.2 SAM：通常只能得到市场边界，不能得到公司的精确可服务市场

模型可以提取：

- 公司实际销售的产品和地区；
- 客户类型和认证要求；
- 监管准入、渠道和交付限制；
- 产能、订单和产品路线；
- 行业总市场中与公司产品相邻的子市场。

但以下信息经常缺失：

- 公司在各产品、地区和客户类型上的可服务比例；
- 客户认证覆盖和可转化采购额；
- 贸易限制对具体市场的量化扣减；
- 公司实际能获得的市场边界。

因此模型可以给出“核心细分市场约为多少”，但不能把它自动称为“公司 SAM”。

### 5.3 SOM：同口径收入份额最容易，产品级份额最难

公开资料足够时，模型可以计算：

```text
广义收入份额 = 公司同口径收入 ÷ 行业同口径收入
数量份额 = 公司同口径出货量 ÷ 行业同口径出货量
```

但必须满足：

- 产品边界一致；
- 地区一致；
- 期间一致；
- 收入与收入、出货与出货相除；
- 实际值与预测值不混用；
- “超过/接近”等区间值不能计算成精确百分比。

### 6.1 模型成功获取并结构化的数据

| 光模块收入占总收入 | 97.95% | 程序派生计算 | 根据年报计算 |

| 光模块产量 | 2,376 万只 | 年报经营表格文档抽取 | 公司年报实际值 |
| 披露产能 | 2,806 万只/年 | 年报经营表格文档抽取 | 公司年报披露值 |
| 境外光模块收入 | 346.14 亿元人民币 | 年报地区/分部表格文档抽取 | 公司年报实际值 |
| 全球光模块及相关产品市场 | 238 亿美元 | Web Search + LightCounting 公开原文抽取 | 行业公开估算，广义口径 |

| 广义收入市场份额 | 约 22.3% | 公司结构化/文档数据 + 行业 Web Search + 程序计算 | 同一机构口径下的近似计算 |

### 6.2 仍不可可靠获取的数据

- 公司 400G、800G、1.6T 各自收入；
- 公司 400G、800G、1.6T 各自销量和 ASP；
- 公司纯数通收入与电信收入的精确拆分；
- 全球 400G、800G、1.6T 各自实际收入；
- 公司实际可服务 SAM；
- 公司在 800G、1.6T 市场的精确份额；
- 客户认证、单一客户采购额和地区可服务比例。

### 6.3 本例中必须避免的错误

以下计算不能作为正式结论：

```text
公司全部销量 ÷ 全球 400G+ 出货量
公司全部光模块收入 ÷ 全球数通光器件收入
50 亿美元 ÷ 超过 190 亿美元
公司光模块收入 ÷ 全球 800G 市场
```

原因分别是产品范围不一致、模块与器件混合、分子分母都是开放区间、公司没有 800G 分产品收入。

## 7. 建议的处理分层

### A 类：可直接进入结构化事实库

- 公司身份和报告元数据；
- 年报、季报中的财务和经营数值；
- 公告事件及公司行动；
- 明确来源的宏观序列；
- 有公开正文的行业数字；
- 有明确口径的公司和同行市场份额。

进入条件：来源链接、发布日期、期间、单位、币种和原文摘录齐全。

### B 类：模型可以提取，但必须程序复核

- PDF 表格和财报附注；
- 分部、客户、地区和产品说明；
- 电话会和管理层指引；
- 行业报告中的产品分类；
- 从公司和同行数据汇总的 TAM/SOM；
- 公司行动和股本稀释历史。

进入条件：原文可回链，且通过主体、期间、单位、边界和重复记录校验。

### C 类：只能作为线索或分析假设

- 搜索摘要和媒体二次引用；
- 付费报告标题但无正文数字；
- “约占”“领先”“数十亿美元”等没有分子分母的说法；
- 模型根据公司产品推测的可服务比例；
- 客户认证、竞争格局和未来订单的间接推断。

这类内容不能直接进入已验证 TAM/SAM/SOM，也不能作为精确市场份额的计算输入。

### D 类：必须保持不可得

- 公司未披露的产品级收入、销量和 ASP；
- 无公开统计口径的客户采购额；
- 无法拆分的行业混合市场；
- 只有开放区间的分子或分母；
- 不同产品、地区、期间之间的强行换算结果。

## 8. 推荐的自动化链路

```text
目标公司 + 证券代码
  → 数据路由器检查结构化来源
  → 结构化 API 获取 K 线、三表、主数据、13F、宏观等确定性字段
  → 模型识别主营与商业模式，列出结构化源缺口
  → Web Search 找缺口对应的公开原文
  → 模型提取事实记录和原文摘录
  → 程序校验主体、期间、单位、币种和产品边界
  → 程序计算可比的派生指标
  → TAM/SAM/SOM 分层输出
  → 缺失、冲突和不可比项目显式阻断
```

建议模型最终同时返回 Markdown 和结构化 JSON。JSON 至少包含：

```json
{
  "evidence_records": [],
  "market_boundaries": [],
  "tam_candidates": [],
  "sam_constraints": [],
  "som_candidates": [],
  "calculations": [],
  "blocked_items": []
}
```

其中每条 Web Search `evidence_record` 至少包含：`subject`、`metric`、`value`、`unit`、`currency`、`period`、`knowledge_type`、`product_scope`、`region_scope`、`source_title`、`source_date`、`source_url` 和 `status`。不要求模型返回原文摘录、页码或段落定位；需要回看时直接打开来源链接。

## 9. 最终判断

模型 + Web Search 适合把原本需要人工翻找的公开资料，快速变成“来源绑定的研究输入”。它可以显著降低资料搜集和初步解析成本，也足以支撑公司边界、行业候选市场、经营事实、事件风险和部分市场份额分析。

它不能替代授权行业数据库，也不能解决公司和行业没有披露的数据。对 TAM/SAM/SOM 最可靠的产品形态不是“模型给出一个数字”，而是：

```text
多个可回链的原始事实
  → 明确市场边界
  → 同口径输入
  → 确定性公式
  → 可计算结果或明确阻断
```

## 10. 页面按需 Web Search 实现契约

页面把 Web Search 做成六个独立信息目标包按钮：`latest_annual_report`（公司经营与结构）、`recent_filings`（经营变化）、`industry_market`、`peer_set`、`forecast_consensus` 和 `event_risk`。内部 `package_kind` 为保持存储兼容可以继续沿用旧名称，但提示词和页面不得把文档类型当成来源限制。其中 `forecast_consensus` 是“外部预测补充”而非研报预测主源：预测与估值页默认只读取项目内部已抽取、来源绑定并经工程口径处理的研报账本；只有用户明确需要该账本之外的公开前瞻材料时才点击它。一次点击只创建或复用一个**持久任务**，HTTP 响应只确认任务状态；本地 runner 在后台完成模型搜索和入库，不依赖页面保持打开。页面首次读取、刷新和切换 Tab 只读任务/信息包状态，绝不调用模型；关闭或刷新页面不会取消已创建的后台任务。

每个包使用 `gpt-5.6-luna`、`high` 思考深度和受控 JSON 模板。模型必须实际调用 Web Search，所有面向用户的内容使用简体中文；每条已验证记录保存本次搜索回链的来源 URL、来源标题、来源发布日期、期间/单位/币种及本地处理时间，不要求连续摘录和精确定位。公司/监管事实与第三方分析必须通过中文陈述中的明确归因区分。结构化主源（行情、三表、证券身份、13F、宏观序列）仍不走 Web Search。

任务与信息包都使用持久化去重键 `security_code + package_kind + package_prompt_version`；每个包独立版本化。原子入队和原子认领保证并发重复点击只会执行一次模型调用；`queued`、`running`、`completed`、`failed` 状态、尝试次数、错误、开始/完成/更新时间都会随刷新返回。相同任务完成后再次点击只复用已保存包；失败任务可显式重新入队。只在模板改变、出现新的法定披露、来源过期、冲突或用户明确扩大范围时才建立新版本，其他包继续复用。模型没有返回搜索引文时任务失败；单条来源 URL 不在本次引文中时保留为未回链信息，不能标为已验证。
