# 每日复盘留痕

> 每个复盘日一份 `YYYY-MM-DD.md`，只记录**当日增量**与**当时的判断依据**。
> 本文目录**不得**写入个人持仓、成本、账户资金、目标价或买卖指令。

## 为什么单独留痕

`config/investment-daily-report.json` 是**当前快照**，每次复盘都会被覆盖；它回答"现在怎么看"。
本目录是**历史序列**，回答"当时依据什么这么看"，以及"后来证明判断错在哪"。

没有这层留痕，回测就没有可信的输入：事后只看到最终动作，看不到当时的证据、假设和未知项，
任何"这套方法有效"的结论都无法证伪。

## 规则

1. **一份日记只对应一个报告日**，文件名必须等于 `reportDate`；同日不得有两份。
2. **只写增量**。没有新事实就写"无实质变化"，不要重复上一日的分析凑篇幅。
3. **估值区间变化必须标注归因**：
   - `filing` = 公司披露了新一期报告（锚点变了）；
   - `model` = 我们改了默认倍数或原型（**不是**公司变化）；
   - `price_source` = 行情源不可用（**不是**估值变化）；
   - `unattributed` = 无法归因，写清为什么，不要硬猜。
4. **新闻与传闻**标注"待一手验证"，且不进 `evidenceRefs`。
5. **多处上市不得自动等价**：A/H/ADR 的价格、货币、交易权利分别记录。
6. 每条有方向的判断都要写**失效条件**——什么事实出现就说明这个判断错了。

## 与 JSON 的关系

| 内容 | 落在哪 |
|---|---|
| 当日覆盖、动作、估值 | `config/investment-daily-report.json`（机器校验） |
| 推理过程、被否掉的假设、归因 | 本目录（人读，脚本只查结构） |
| 估值区间快照 | `reports/valuation-bands/YYYY-MM-DD.json`（git-ignored） |

结构校验：`npm run check:daily-notes`。它只检查日期、必填字段和章节是否齐全，
**不判断分析质量**——那需要人读。

## 生成快照与差异

```bash
node scripts/snapshot-valuation-bands.mjs            # 采集当日快照并与上一份对比
node scripts/snapshot-valuation-bands.mjs --dry-run  # 只看差异，不落盘
```

差异输出按 `filing` / `model` / `price_source` / `unattributed` 分组，直接作为
"估值区间变化"一节的输入。
