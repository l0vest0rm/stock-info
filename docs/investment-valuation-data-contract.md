# 观察池估值数据口径：缺口与已补齐部分

> 记录日期：2026-10-27。与 `docs/archive/investment-valuation-framework-draft-2026-10-27.md`（方法框架草案）配套。
> 本文只说明“现在能算出什么、还算不出什么”，不含价格、目标价或买卖结论。

## 0. 数据来源（就是仓库现成接口）

| 用途 | 接口 |
|---|---|
| 单期利润表（累计 + 单季两个家族） | `GET /api/finance/income?code=` |
| 资产负债表 | `GET /api/finance/balance?code=` |
| 现金流量表 | `GET /api/finance/cashflow?code=` |
| 标准化模型（含币种/口径/来源健康度） | `GET /api/finance/{type}?code=&format=read-model` |
| 财务质量分析 | `GET /api/research/company/{code}/financial-analysis` |
| 估值口径中间量（本轮新增，内部复用上述取数） | `GET /api/finance/valuation-inputs?code=` |
| 季度序列与 TTM（本轮新增，内部复用上述取数） | `GET /api/finance/income/quarterly-series?code=&limit=` |

底层链路：本地缓存 `data/local/market-data/financial-statements/` → 东方财富 F10（A股 `RPT_F10_FINANCE_{G,B,S,I}*`，港股 `RPT_HKF10_FN_MAININDICATOR`）→ 美股 Yahoo Finance。没有新增外部数据源。

### 行情字段：价格小数位与市值（已修复）

东财 `push2delay` 的 `GET /api/qt/stock/get` 是公司信息栏与估值筛选的唯一行情来源。三个字段必须一起读，缺一个就会静默错一位数量级：

| 字段 | 含义 | 注意 |
|---|---|---|
| `f59` | `f43`/`f169` 的小数位数 | A 股 = 2（`f43=4243` → 42.43），**港股/美股 = 3**（`f43=386400` → 386.4） |
| `f43` | 最新价，需按 `f59` 缩小 | 写死 ÷100 会让港股价格放大 10 倍 |
| `f116` | 总市值，**原值（元/港元/美元），不缩放** | 除以 `1e8` 得「亿」 |

此前 `priceDivisor` 写死 `100`，于是港股价格被放大 10 倍。表面看只是价格错，实际连带两个后果：

1. `/company.html` 信息栏的「市值(亿)」= 股价 × 总股本。总股本由「市值 ÷ 股价」反推，价格放大 10 倍会让股本缩小 10 倍，市值就少报一个数量级（腾讯曾显示 3515 亿而非 35152 亿）。
2. 港股 K 线来自雪球且**不含 `market_capital`**，`applyXueqiuKlineOverview` 曾无条件用雪球市值覆盖东财市值，把东财本来有的值抹成 `null`。现在规则是「雪球有值才覆盖」，价格仍以雪球为准。

同时 `fetchShareChange` 曾对非 A 股直接 `return []`，跳过了后面「市值 ÷ 股价反推股本」的兜底，因此港股总股本恒为空、页面恒显示「暂无数据」。现在早退只用于跳过 A 股 F10 报表（`RPT_F10_EH_EQUITY`），兜底逻辑对所有市场生效。

实测（2026-10-28）：

| 代码 | 价格 | 市值(亿) | 反推股本 |
|---|---|---|---|
| 00700.HK 腾讯控股 | 386.8 | 35152 | 90.93 亿 |
| 09988.HK 阿里巴巴-W | 97.3 | 19365 | 199.02 亿 |
| 01299.HK 友邦保险 | 70.2 | 7269 | 103.47 亿 |
| 00388.HK 香港交易所 | 366.6 | 4648 | 12.68 亿 |
| 09633.HK 农夫山泉 | 40.22 | 4521 | 112.46 亿 |

**取数失败 ≠ 没有市值。** `push2delay` 对本机会间歇性 `UND_ERR_SOCKET`（IPv6 连接被对端关闭），同一 URL 重试即可成功。筛选器因此区分 `quote_fetch_failed`（重试三次仍失败）与 `quote_missing`（响应成功但 `f116` 为空），两者不可互换。

### 页面估值字段：PE(TTM) 也必须由服务端给（已修复）

`/company.html` 信息栏的「市值(亿)」与「PE(TTM)」原本都在浏览器里现算：

- 市值 = 股价 × 总股本，总股本取 `/api/finance/sharechange`。
- PE(TTM) = 市值 ÷ 「最近 4 行净利润之和」。

第二个公式的输入是 `/api/finance/income` 的原样行，而该接口**并列**返回两个家族：`*INCOME`（年初至今累计：一季报/中报/三季报/年报）与 `*INCOMEQC`（该季度单独值）。把「最近 4 行」相加，等于把一个整年利润当成一个季度、把中报当成二季度。实测：

| 代码 | 页面旧值 | 服务端权威值 | 原因 |
|---|---|---|---|
| 00700.HK 腾讯控股 | 6.23 | **14.93** | 2025 年报 2248 亿被当成一个季度加入 |
| 600519.SH 贵州茅台 | 10.86 | **20.58** | 中报累计 445 亿被当成二季度 |

两个数都「看起来像个 PE」，没有 NaN、没有空值，所以只能靠交叉核对发现。修复方向不是在前端补齐日历逻辑（那是第二份实现，必然与服务端漂移），而是：

1. `web/src/modules/company/domain/pe-ttm.ts` 的 `trailingQuarterlyParentNetProfits` 只接受**真正的单季行**（`*_incomeqc.v1` 契约，或 `一季度`…`四季度` 标签）；累计行一律剔除。港股 `RPT_HKF10_FN_MAININDICATOR` 只发布累计口径，因此该函数对港股返回 `[]` —— 页面显示「暂无数据」，而不是拿累计数凑一个 PE。
2. `legacy-runtime.ts` 的 `calculateAndDisplayValuation` 不再自己算 PE，改为读取 `/api/company/info` 的 `peTtm`（服务端 `loadLatestFinancialValuation` 已按财年基期 + 累计滚动算好）。

K 线图里的「市盈率TTM」序列仍走同一个 helper，因此同样只对 A 股出数；港股曲线为空是诚实结果，不是取数失败。

自检：`npm run check:web-pe-ttm`（7 组用例，含「只有累计行必须返回空」「混合负载只留单季」「年报行不得混入」「四个季度不连续必须拒绝」）。

### 12-31 的两条记录（已修复）

东财 A 股利润表同时返回 `*INCOMEQC` 的单季行与 `*INCOME` 的年报行，因此 12-31 会出现两条：四季度（单季）与 12M（全年）。TTM 公式必须以年报行为基期。此前 `effectiveRows` 按日期去重时 Q4 行会覆盖年报行，导致 `previousAnnual` 取不到、PE(TTM) 静默返回 `null`。

修复后（`src/modules/finance/application/latest-financial-valuation.ts`）：年报行改用独立键保留，并与同日 Q4 行并存，`trailingTwelveMonths` 显式查找年报行；若年报缺失则返回 `null`，绝不让 Q4 冒充全年。

实测（2026-10-27 收盘，2026-06-30 中报）：中际旭创 PE 41.69 / PS 12.97 / PCF 71.71 恢复；茅台 20.92 / 6.75 / 9.97；兴业银行 5.36 / 0.43；中芯国际 118.88；美的集团 14.71。`npm run test:basic` 通过。

自检：`npm run check:ttm-annual-base`。

### 财年基期不能由 12-31 推断（已修复）

TTM 恒等式是「上年报 + 本期累计 − 上年同期累计」，唯一的自由参数是**哪一行算上年报**。此前代码在四处都把这个参数写死成「日期为 12-31 的那一行」，只有财年恰好 12 月结束的公司才成立。

阿里（`09988.HK`）财年 3-31 结束。最新行是 6 月季报，旧代码去找 `2025-12-31`，拿到的是**三季报**，于是 TTM 净利算成 480.16 亿，真实值 735.57 亿——**低估 35%**，而区间依然标 `available`。

同一个假设造成四处后果，现全部收敛到 `src/modules/finance/domain/ttm-fiscal-calendar.ts`：

| 位置 | 后果 |
|---|---|
| `load-valuation-bands.ts` 的 `trailingCumulative` | 阿里 TTM 净利低估 35% |
| `load-valuation-bands.ts` 的 `ttmCapitalExpenditure` | 同一假设；A 股现金流无契约字段，改用 `REPORT_TYPE=年报` 判定 |
| `latest-financial-valuation.ts` 的 `trailingTwelveMonths` | 阿里 PE(TTM) 恒为 `null`（找不到「上年报」） |
| `quarterly-ttm-series.ts` 的 `incomeFamilyOf` | 港股行按「无契约 → 单季」处理，累计列全空、累计值被塞进单季列、TTM 全空 |

判定规则：财年基期只认数据源声明的年报行——港股 `DATE_TYPE_CODE=001`，A 股 `*INCOME` 年报家族，现金流 `REPORT_TYPE=年报`，Yahoo `FISCAL_PERIOD=12M`。**12-31 本身不是年报的证据。**上年同期按财年基期的月份偏移计算，不按自然年减一。

自检：`npm run check:ttm-fiscal-calendar`（3-31 财年 / 12-31 财年 / 最新即年报 / 只有年报+中报 / 现金流无契约 / 缺年报降级为 null）。

### 季度序列：`GET /api/finance/income/quarterly-series?code=&limit=`

两个口径本来就是东财的两个独立接口族，不需要推算：

| 家族 | 东财报表 | 返回 | 行标签 |
|---|---|---|---|
| 当年累计 | `*INCOME`（`GINCOME` / `BINCOME` / `IINCOME` / `SINCOME`） | 年初至今累计 | 一季报 / 中报 / 三季报 / 年报 |
| 单季度 | `*INCOMEQC` | 该季度单独值 | 一季度 / 二季度 / 三季度 / 四季度 |

本接口直接读取两者并并列输出，`limit` 默认 8、上限 40。**不做累计相减，也不做口径猜测。**

| 字段 | 含义 |
|---|---|
| `families` | 本次实际取到的家族：`{cumulative, quarterized}` |
| `points[].cumulativeRevenue/cumulativeNetProfit` | `*INCOME` 的当年累计值 |
| `points[].quarterRevenue/quarterNetProfit` | `*INCOMEQC` 的单季度值 |
| `points[].ttmRevenue/ttmNetProfit` | TTM，只在累计口径上有定义 |
| `points[].ttmBasis` | `annual`（该点是年报，TTM 即年报）/ `cumulative_roll`（上年报+本期累计−上年同期累计） |
| `points[].revenueYoY/netProfitYoY` | 单季同比，用完整历史解析后再裁剪 |
| `points[].gaps` | 该点算不出的字段 |
| `complete` | 返回区间内每个点的 TTM 营收与净利都非空 |

规则：

1. 12-31 同时存在三条观察：年报累计、四季度单季、以及中间期表可能带出的累计行，三者互不覆盖。
2. TTM 缺上年报时返回 `null`，绝不用四季度冒充全年。
3. 两个家族任一缺失时如实上报：缺 `*INCOME` → 无 TTM，但单季值可用；缺 `*INCOMEQC` → 有 TTM，但无单季值与同比。
4. 读取层把这些缺失变成结构化 warning（`FinancialStatementReadModel.warnings`）：`missing_cumulative_income_family` / `missing_annual_income_statement`，附带实际取到的 `families`。不再静默降级。

|---|---|---|---|---|---|
| 300308.SZ 中际旭创 | 2026-06-30 | 417.78 | 222.81 | 652.29 | +174.6% |
| 600519.SH 贵州茅台 | 2026-06-30 | 922.78 | 375.75 | 1732.38 | −5.2% |
| 000858.SZ 五粮液 | 2026-09-30 | 328.58 | 44.42 | 427.49 | −37.7% |

- **单季相加 = 累计**：中际旭创 194.96 + 222.81 = 417.78；茅台 547.03 + 375.75 = 922.78；五粮液 228.38 + 55.79 = 284.17；宁德 1291.31 + 1477.86 = 2769.17；比亚迪 1502.25 + 1945.90 = 3448.15；中芯 176.17 + 210.18 = 386.35；兴业 550.90 + 550.87 = 1101.77。

### 金融家族（银行 / 保险）单独核对

`BINCOME` / `IINCOME` 族的营收落在 `OPERATE_INCOME`，而 `TOTAL_OPERATE_INCOME` 恒为 `0`；且这两个族**不发布年内中间期的单季度行**（`*INCOMEQC` 只有一季度和年报对应的四季度）。这带来两个结论：

1. **TTM 必须从累计族取**，不能依赖单季度行齐全。原实现按 5 个报告期取数，招商银行与中国平安恰好在当前季度缺上年同期行，`ttm*` 全为 `null`。现改为 8 个报告期（`src/adapters/eastmoney-report-window.ts`），保证恒有三个锚点：上年报、本期累计、上年同期累计。
2. **银行/保险的单季度同比不可用并非缺陷**，而是源头没有该行；接口会如实写入 `gaps` 与 `limitations`。

### 财报取数窗口

`genReportDates(8)` 是唯一的窗口定义，纯函数模块 `src/adapters/eastmoney-report-window.ts`。窗口必须同时覆盖三个 TTM 锚点，**不能压缩回 5 个报告期**——这正是招商银行/中国平安 `ttm*` 为空的根因。自检：`npm run check:income-window`。

### 折旧摊销与 EBITDA

**数据源**：现金流量表**补充资料**块（`GCASHFLOW`）。字段：

| 字段 | 含义 | 是否相加 |
|---|---|---|
| `FA_IR_DEPR` | 固定资产折旧、油气资产折耗、生产性生物资产折旧 | 主项 |
| `OILGAS_BIOLOGY_DEPR` | 与 `FA_IR_DEPR` **同一科目的别名**（实测差 <1e-5） | ❌ 不相加 |
| `IA_AMORTIZE` | 无形资产摊销 | ✅ |
| `LPE_AMORTIZE` | 长期待摊费用摊销 | ✅ |
| `USERIGHT_ASSET_AMORTIZE` | 使用权资产摊销 | ✅ |

**关键约束：补充资料只在年报和中报披露。** 实测 175 个现金流量表行里，年报/中报全部有值，一季报/三季报 `FA_IR_DEPR` 恒为 `0`，且同期的 `NETPROFIT`、`NETCASH_OPERATENOTE` 也是 `0` —— 这是整块未披露，不是零折旧。直接用最新期数值会得到"折旧为 0"的错误结论。

因此按报告期分四种口径，都写进 `limitations`：

| `basis` | 条件 | 取值 |
|---|---|---|
| `annual` | 最新期是年报 | 该年报补充资料 |
| `trailing_twelve_months` | 最新期是中报或三季报，且上年报与上年同期都有值 | 上年报 + 本期 − 上年同期 |
| `prior_fiscal_year` | 最新期是一季报/三季报，且补充资料为空 | 沿用最近年报，并明确标注 |
| `unavailable` | 全窗口都没有补充资料 | `null`，EBITDA 不可计算 |

保险（`IINCOME`/`ICASHFLOWQC`）**全部报告期都不提供补充资料**，中国平安因此永远落到 `unavailable`。

**已接受的方法论限制**：折旧摊销不用估算值。宁可 `null` + 显式 `gap`，也不给一个看起来能算的假数。

|---|---|---|---|---|---|
| 300308.SZ 中际旭创 | 2026-06-30 | 11.31 | 滚动 | 165.05 | 176.36 |
| 600519.SH 贵州茅台 | 2026-06-30 | 23.50 | 滚动 | 613.88 | 637.38 |
| 300750.SZ 宁德时代 | 2026-09-30 | 269.37 | 沿用年报 | 693.78 | 963.14 |
| 002594.SZ 比亚迪 | 2026-06-30 | 823.32 | 滚动 | 146.95 | 970.27 |
| 688981.SH 中芯国际 | 2026-06-30 | 308.55 | 滚动 | 54.79 | 363.34 |

**交叉验证**：比亚迪 2025 年报可做现金流恒等式回算 —— 净利润 337.61 + 折旧摊销 805.26 + 资产减值 18.23 − 存货增加 239.70 − 经营性应付减少 371.98 ≈ 591，与经营现金流 591.36 吻合。折旧数值本身可信。

**必须注意的倍数陷阱**：比亚迪与中芯国际的折旧摊销约为 EBIT 的 5.6 倍，中际旭创仅 0.07 倍。同一把 EV/EBITDA 尺子量这两类公司，会把重资产制造显著低估。EV/EBITDA **不能跨资本密度直接比较**，必须与 EV/EBIT 并列看；用 EV/EBITDA 时须注明资本密度差异。

### 资本密度与倍数分档

**为何要分档**：`EV/EBITDA` 剔除折旧摊销，而折旧摊销占 EBIT 的比例在不同业务间相差 400 倍。

全量实测（`npm run audit:capital-intensity`，78 家 A 股，69 家可测）：

| 档位 | 折旧/EBIT | 家数 | 代表 |
|---|---|---|---|
| 轻 | < 0.5 | 34 | 贵州茅台 0.04、中际旭创 0.07 |
| 中 | 0.5 – 1 | 19 | 中国海油 0.74、美的集团 0.98 |
| 重 | > 1 | 16 | 比亚迪 5.60、中芯国际 5.63、长城汽车 4.52、启明星辰 17.07 |
| 无法判定 | — | 9 | 3 银行 + 2 保险（不披露补充资料），及 4 家其他 |

因此 `EV/EBITDA` 区间按档位取值：轻 14–28 倍、中 9–18 倍、重 5–11 倍。`EV/EBIT` 保持单一区间，因为它已经包含折旧。

**可比性门禁**（`comparability-matrix.ts`）：两条公司可比某一指标，必须同时满足

1. 业务原型相同
2. 资本密度档位相同（仅对 `ev_ebitda`、`ev_revenue`、`pb`、`fcf_yield` 生效）
3. 该指标不被任一方原型禁用
4. 双方都有该口径的分母
5. 周期股的利润类倍数要求双方中枢利润都成立

被拒绝的比较会带原因返回，不会静默消失。

### 周期中枢利润

**定义**：取最近 5–10 个**年报**的归母净利润，报告**中位数**（主）与均值（并列）、最小值/最大值、变异系数、峰值/中枢。

**为什么用中位数**：中远海控 2016–2025 的均值 313.56 亿被 2021–2022 两个超级景气年拉高，而中位数 168.94 亿更接近正常经营水平。两者相差 46% 时，模块会显式提示「单一年份主导，优先参考中位数」。

**硬规则**：

- 只用年报。中报/三季报是累计口径，混入会让最新一年被重复加权
- 缺年份报缺，不插值、不用 TTM 或季度补齐
- 少于 5 个年报 → `insufficient_data`，不给中枢值
- **亏损年份保留**。剔亏损会系统性抬高中枢
- 原型非 `cyclical_commodity` 时，该方法是 `forbidden_for_archetype`

**取数**：A 股用 `RPT_F10_FINANCE_GINCOME` 一次请求 11 个年末，实测单页可返回全部（紫金矿业 2011–2025 共 15 行）。港股/美股退回常规快照已有年报表，历史不足则如实报 `insufficient_data`。

**锚点必须是日期，不能是窗口标签。** `window` 形如 `2016..2025`，是给人看的区间描述；曾把它直接写进 `denominator.reportDate`，后果有两层：

1. 锚点无法解析成日期，任何依赖日期的判断（陈旧度、快照对比）都会失效——周期股因此**永远**被判"无法确认同一时点"；
2. 快照 diff 会把 `"2016..2025" → "2025-12-31"` 读成"锚点变新了"，从而把**我们自己修锚点**记成 `filing`，即把模型修正写成公司披露。

现在锚点取 `years[]` 里最新一条年报的 `reportDate`（`2025-12-31`），窗口只留在 `assumptions` 里做说明。若窗口内没有任何带日期的年报，区间为 `insufficient_data` 并写明「中枢窗口内没有可用的年报报告期」，不回退到窗口字符串。

### 区间角色由原型决定

`role`（`primary` / `auxiliary`）是**业务原型**的属性，不是最新财报的属性：同一原型下所有公司的区间角色一致。因此：

- 银行/保险的 `pe_ttm` 是 `auxiliary`。原型定义原文是「PE 辅助，不单独使用」——银行的利润受拨备与减值影响，保险的利润受投资收益与准备金假设影响，二者都不能用通用 8–18x 的 PE 区间定价值。曾把两者设为 `primary`，结果是所有银行显示 60–70% 的虚假安全边际。
- 周期股的 `pe_ttm` 也是 `auxiliary`，由 `pe_mid_cycle` 承担主方法。
- 角色变化在快照里归因为 `model`（**不是** `filing`），因为角色由原型静态决定，公司披露无法改变它。

### 收益率区间的锚点

`fcf_yield` / `dividend_yield` 的 `reportDate` 取自现金流表报告期（缺则退回利润表报告期）。此前固定写成空字符串，导致收益率区间无法判断新鲜度，任何按日期校验的消费方只能整条拒绝。

### PE(TTM) 修正留痕

修累计口径之前，TTM 是用"上年报 + 单季度被当成累计"滚出来的，净利偏低、PE 偏高。修正后：

| 项目 | 修正前 | 修正后 | 说明 |
|---|---|---|---|
| 中际旭创 TTM 归母净利 | 163.02 亿 | **204.53 亿** | 107.97（2025 年报）+ 136.51（2026 中报累计）− 39.95（2025 中报累计） |
| 中际旭创 PE(TTM) | 41.69 | **33.23** | 41.69 是错的 |
| 中际旭创 PS(TTM) | 12.97 | **10.42** | 同上，分母是 TTM 营收 652.29 亿 |

手算复核（`/finance/income/quarterly-series?code=300308.SZ`）：

```
累计净利  2025-12-31 年报     107.97
          2026-06-30 中报     136.51
          2025-06-30 中报      39.95
TTM = 107.97 + 136.51 − 39.95 = 204.53   ✅ 与接口 204.5329 亿一致
ttmBasis = cumulative_roll
```

单季度侧同时自洽：57.35（Q1）+ 79.17（Q2）= 136.51，即累计中报。

其余验证公司在修正后均正常返回：贵州茅台 PE 20.81 / PB 6.75、五粮液 PE 22.36 / PB 2.47、比亚迪 PE 25.40 / PB 2.87、中芯国际 PE 118.80 / PB 4.99、兴业银行 PE 5.36 / PB 0.43。

> 注意：倍数会随价格变动，上表只用于证明"分母口径已修正"，不是估值结论。

## 1. 现状：通用估值口径只有一个公式

现有估值链路（`src/modules/finance/application/latest-financial-valuation.ts`）对每只证券只算四个指标：

| 指标 | 公式 | 数据来源 |
|---|---|---|
| PE(TTM) | 市值 ÷ 归母净利润TTM | 利润表 + 市值 |
| PB | 市值 ÷ 归母权益 | 最近资产负债表 |
| PS(TTM) | 市值 ÷ 营业收入TTM | 利润表 |
| PCF(TTM) | 市值 ÷ 经营现金流TTM | 现金流量表 |

对制造业、消费、互联网软件是够用的起点；对**银行、保险、券商、资源周期、REIT/不动产运营**会系统性失真，因为它们的主指标不是净利润或营业收入。

## 2. 本轮补齐：`GET /api/finance/valuation-inputs?code=`

新增 `src/modules/finance/domain/valuation-inputs.ts`（纯函数）与 `src/modules/finance/application/load-valuation-inputs.ts`（取数），复用现有三表读取与“最新期 + 上年同期”两期口径。

输出内容：

| 字段 | 含义 | 用途 |
|---|---|---|
| `revenue` / `operatingIncome` / `netProfit` / `parentNetProfit` / `minorityProfit` | 利润表中间项 | 分部、少数股东剔除 |
| `totalParentEquity` / `totalEquity` / `minorityEquity` / `totalAssets` | 权益与少数股东 | PB-ROE、EV 中的少数股东处理 |
| `grossDebtDisclosed` | 已披露有息负债合计（短借+一年内到期+长借+债券+租赁负债） | 净负债、EV |
| `cashDisclosed` | 货币资金 + 交易性金融资产 | 净负债、EV |
| `ebit` | 营业利润 − 投资收益 − 公允价值变动 | EV/EBIT、利率敏感性 |
| `ebitda` | EBIT + 折旧摊销 | EV/EBITDA（注：折旧摊销交易所标准三表无对应字段，缺失时**不计算**，不猜） |
| `operatingCashFlow` | 经营现金流 | FCF 收益率、股息覆盖 |
| `periods` | 三期分别的最新/上年同期日期、币种 | 防止跨期、跨币种混算 |
| `balanceSheetArchetype` / `revenueArchetype` | 非金融/银行/保险/券商 | 决定哪些指标允许使用 |
| `gaps` | 缺失字段清单（含原因） | 报告里明确写“缺失”，而不是当 0 |
| `limitations` | 口径限制说明 | 防止把代理指标当报表科目 |

关键设计：

1. **银行/保险/券商自动关闭 EBIT/EBITDA/EV 与营收倍数**，只保留权益类指标，避免用错口径。
2. **有息负债是“已披露合计”**，缺哪一项就进 `gaps`，不会把缺失科目当零。实测银行/保险的 `grossDebtDisclosed` 会把租赁负债、应付债券混入，因此金融股的该字段一律不可用。
3. **TTM 仍不在本接口里**：本接口用“最新一期 + 上年同期”做同比，TTM 的滚动加总仍在现有 `latest-financial-valuation`，两者不要混用。
4. **不分担估值口径的换算**：A/H/ADR 的币种、存托比例仍要在调用方显式给出。

### 本地实测（2026-10-27，报告期 2026-06-30）

| 证券 | 类型判定 | EBIT | 说明 |
|---|---|---|---|
| 600519.SH 贵州茅台 | non_financial | 238.49 亿 | 营业利润 238.74 亿扣投资收益后可用；EBITDA 因缺折旧摊销不可算 |
| 300308.SZ 中际旭创 | non_financial | 95.36 亿 | 同上 |
| 600036.SH 招商银行 | bank | 不计算 | 已按设计关闭 EV/EBIT |
| 601318.SH 中国平安 | insurer | 不计算 | 已按设计关闭 EV/EBIT |

结论：制造业/消费类的 EV 分子已经能自动产出；金融类目前只有权益与规模字段，专用口径仍缺。

## 4. 使用规则

1. 每个估值结论必须写成“同证券 + 同日期 + 同币种 + 口径名”。
2. 只有 `gaps` 为空、且主方法所需字段齐全的公司，才能进入“可考虑买入/增持”候选。
3. `provisional=true`（业绩快报/未正式披露）可以作为研究线索，但不得作为交易依据。
4. 银行、保险、REIT 在专用口径补齐前，只能用 PB、P/EV、股息率做相对观察，不做目标价。
